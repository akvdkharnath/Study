Most commonly used status codes are:
200 - OK - The request has succeeded.
201 - CREATED - Resource successfully created (used in POST or PUT methods).
202 - ACCEPTED - The request has been accepted for processing, but processing is not complete.
204 - NO CONTENT - The server successfully processed the request but there is no content to return.

301 - MOVED PERMANENTLY - The URL of the requested resource has been changed permanently.
302 - FOUND - The resource resides temporarily under a different URI (commonly used for temporary redirects).
304 - NOT MODIFIED - Used in conditional GET requests to reduce bandwidth; no content is returned.
307 - TEMPORARY REDIRECT - The request should be repeated elsewhere, method unchanged.
308 - PERMANENT REDIRECT - The request, and all future requests, should be repeated using another URI.

400 - BAD REQUEST - The server cannot or will not process the request due to client error (validation, missing data, etc.).
401 - UNAUTHORIZED - Returned when there are no valid authentication credentials sent with the request.
403 - FORBIDDEN - User does not have access (or is forbidden) to the resource.
404 - NOT FOUND - Resource/method is not available.
405 - METHOD NOT ALLOWED - The method is not allowed for the requested URL.
409 - CONFLICT - Request could not be processed because of conflict in the current state of the resource.
410 - GONE - Resource requested is no longer available and will not be available again.
415 - UNSUPPORTED MEDIA TYPE - The server does not support the media type transmitted in the request.
422 - UNPROCESSABLE ENTITY - The request was well-formed but contains semantic errors.
429 - TOO MANY REQUESTS - Rate limit exceeded.

500 - INTERNAL SERVER ERROR - Server encountered an unexpected condition.
501 - NOT IMPLEMENTED - The server does not support the functionality required.
502 - BAD GATEWAY - Server received an invalid response from an upstream server.
503 - SERVICE UNAVAILABLE - Server is currently unable to process the request due to maintenance, overload, or temporary issues.
504 - GATEWAY TIMEOUT - Server acting as a gateway did not receive a timely response from the upstream server.


HTTP Methods:

GET:
- fetch/read data from server.
- Should not modify data (safe, read-only).
- Parameters may be sent via URL (query string).
- Idempotent (multiple identical requests have same effect).

POST:
- create a new resource on the server.
- Not idempotent (multiple identical requests may create multiple resources).

PUT:
- create or fully update/replace a resource at a specific URI.

DELETE:
- Used to delete the specified resource from the server.
- Idempotent (deleting a resource multiple times has same effect: resource gone).

PATCH:
- partially update/modify an existing resource.
- Only the specified changes are sent (not the whole resource).
- Not always idempotent (depends on server implementation).
- Preferred when only small changes are needed.

OPTIONS:
- Used in CORS preflight requests.
- Returns a list of supported HTTP methods for the endpoint (via Allow header).

HEAD:
- Same as GET but only fetches HTTP headers (no response body).
- Check existence or metadata of a resource (e.g., Content-Length, Last-Modified).
- Safe and idempotent.

PUT vs POST vs PATCH

PUT: Update full resource, idempotent, high bandwidth.
PATCH: Update partial resource, often not idempotent, low bandwidth.
POST: Create new resource, not idempotent, high bandwidth.

FLASK PRODUCTION LIMITATIONS & ALTERNATIVES

Why Flask Cannot Be Deployed Directly in Production:

1. DEVELOPMENT SERVER LIMITATIONS:
   - Flask's built-in server is single-threaded
   - Can only handle one request at a time
   - Not designed for concurrent requests
   - No process management or auto-restart
   - No load balancing capabilities
   - Security vulnerabilities in production

2. PERFORMANCE ISSUES:
   - Synchronous request handling
   - No async/await support natively
   - Limited scalability
   - Memory leaks over time
   - No connection pooling by default

3. SECURITY CONCERNS:
   - Debug mode exposes sensitive information
   - No built-in security headers
   - Vulnerable to common web attacks
   - No rate limiting or throttling

4. MONITORING & LOGGING:
   - Basic logging capabilities
   - No built-in metrics collection
   - Limited error tracking
   - No health check endpoints

WSGI SERVERS FOR FLASK (Production Solutions):

1. GUNICORN:
   - Pre-fork worker model
   - Multiple worker processes
   - Easy configuration
   - Good for CPU-bound tasks
   - Command: gunicorn -w 4 -b 0.0.0.0:8000 app:app
   - Workers = (2 * CPU cores) + 1

2. uWSGI:
   - High performance
   - Supports multiple protocols
   - Complex configuration
   - Good for high-traffic applications
   - Can run behind Nginx/Apache


4. MOD_WSGI (Apache):
   - Apache module
   - Good integration with Apache
   - Windows support
   - Enterprise-grade

FLASK ALTERNATIVES FOR PRODUCTION:

1. FASTAPI:
   - Modern, fast web framework
   - Built-in async support
   - Automatic API documentation
   - Type hints and validation
   - High performance (comparable to Node.js)
   - Native WebSocket support
   - Better for microservices

2. DJANGO:
   - Full-featured web framework
   - Built-in admin panel
   - ORM included
   - Security features built-in
   - Good for large applications
   - Production-ready out of the box

WHEN TO USE FLASK vs ALTERNATIVES:

Use Flask when:
- Building simple APIs
- Prototyping quickly
- Small to medium applications
- Team familiar with Flask
- Need flexibility and minimalism

Use FastAPI when:
- Building modern APIs
- Need high performance
- Want automatic documentation
- Working with async operations
- Building microservices

Use Django when:
- Building full web applications
- Need admin panel
- Complex data models
- Team productivity is priority
- Enterprise applications

PERFORMANCE COMPARISON (Requests per second):

Standalone servers (no Gunicorn/Uvicorn):

- Flask (built-in dev server): ~300 RPS
- FastAPI (with built-in Uvicorn): ~3,000 RPS

With production servers:

- Flask + Gunicorn: ~2,000 RPS
- FastAPI + Uvicorn: ~8,000 RPS
- Django + Gunicorn: ~1,500 RPS
- Quart + Hypercorn: ~3,000 RPS
