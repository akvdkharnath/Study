SOAP: (Simple Object Access Protocol)
framework used to exchange data from different applications developed in different languages
       1. Function - Driven
       2. API calls can not be cached
       3. WL Security, SSL 
       4. More band and cpu power
       5. XML
       6. HTTP, UDP, SMTP


REST: (Representational State Transfer)
its advanced version of SOAP to transfer data in many types 
       1. Data - Driven
       2. API calls can be cached
       3. HTTPS, SSL
       4. less cpu power and band 
       5. XML, JSON, YAML, Plain Text ect,.
       6. HTTP

principles:
1. Client-server model
2. Uniform interface (every one must follow HTTP or HTTPS only)
3. Stateless
4. Layered system
5. Cacheable

1xx - represents informational responses
2xx - represents successful responses
3xx - represents redirects
4xx - represents client errors
5xx - represents server errors

Most commonly used status codes are:
200 - success/OK
201 - CREATED - used in POST or PUT methods.
202 - ACCEPTED - request has been accepted for processing but processing is not complete
204 - NO CONTENT - server successfully processed the request but there is no content to return
304 - NOT MODIFIED - used in conditional GET requests to reduce the bandwidth use of the network. Here, the body of the response sent should be empty.
400 - BAD REQUEST - This can be due to validation errors or missing input data.
401 - UNAUTHORIZED - This is returned when there is no valid authentication credentials sent along with the request.
403 - FORBIDDEN - sent when the user does not have access (or is forbidden) to the resource.
404 - NOT FOUND - Resource method is not available.
422 - UNPROCESSABLE ENTITY - request was well-formed but contains semantic errors
429 - TOO MANY REQUESTS - rate limit exceeded
500 - INTERNAL SERVER ERROR - server threw some exceptions while running the method.
502 - BAD GATEWAY - Server was not able to get the response from another upstream server.
503 - SERVICE UNAVAILABLE - server was unable to process the request due to maintenance, overloading, or another temporary interference.
504 - GATEWAY TIMEOUT - server acting as a gateway did not receive a timely response


HTTP Methods:
GET: This is used for fetching details from the server and is basically a read-only operation.
POST: This method is used for the creation of new resources on the server.
PUT: This method is used to update the old/existing resource on the server or to replace the resource.
DELETE: This method is used to delete the resource on the server.
PATCH: This is used for modifying the resource on the server.
OPTIONS: This method fetches all the various HTTP methods that are supported.
HEAD: This method is similar to GET but returns only the headers without the response body.
TRACE: This method is used for debugging and returns the received request back to the client.

PUT VS POST VS PATCH

PUT:
1. UPDATE operations
2. updates whole resource
3. idempotent
4. High Bandwidth 

PATCH:
1. UPDATE operations
2. updates part of the resource
3. not idempotent
4. Less Bandwidth 

POST:
1. CREATE operations
2. create new resource
3. not idempotent
4. High Bandwidth

WSGI: Web Server Gateway Interface 
PEP 3333
framework: Django, Flask, bottle
Eg: Gunicorn, uWSGI, apache (mod_wsgi, mod_python)
No async and await 

Gunicorn:
Easy Setup
Reliable

Fast
Simple

no need to proxy
good for better loads

Easy Setup
Faster

overhead

mostely used while using NGINX, Apache, Cherokee
