Memory Management:

In python every thing is an object 

Ram will have 2 types of memory:
1. Stack Memory : Static Memory Allocation, will store  refernce variables and functions calls 
2. Heap Memory (Private Heap Space) : Dynamic Memory Allocation, Objects will be stored here

```python
a = 10
b = 20
c = a + b
```

here a, b, c are reference variables  stored in stack memory 
10, 20 are objects stored in heap memory

```python 
def calculate(x, y):
    result = x + y
    message = f"Result: {result}"
    return message

name = "Alice"
value = 42
final = calculate(10, 20)
```

here once the function is called a stack frame is created 

1. x,y are local variables stored in stack memory and 10, 20 are objects stored in heap memory
2. result is a local variable stored in stack memory and 30 is an object stored in heap memory
3. message is a local variable stored in stack memory and "Result: 30" is an object stored in heap memory
4. Once after execution of the function the stack frame is popped and all the local variables (x,y,result,message) are deleted 
5. But the objects (10, 20, 30, "Result: 30") are still in heap memory and will be deleted when the reference count is 0


Key Differences: Stack vs. Heap in Python

Stack:
1. Stores references/variable names, function parameters
2. Allocated automatically at function call
3. Deallocated automatically at function return (LIFO)
4. Extremely fast (contiguous memory)
5. Limited (per thread)
6. LIFO stack structure
7. Duration of function execution
8. Each thread has own stack

Heap:
1. Stores all actual Python objects
2. Allocated at object creation (runtime)
3. Deallocated when reference count reaches 0 (reference counting) + GC
4. Slower (fragmentation, indirect access)
5. Large, flexible
6. Dynamic allocation
7. Until no references exist
8. Shared among threads, requires GC


Python memory manager divide the heap memory into 3 parts 

1. Block: Smallest unit of memory allocation, 8 to 12 bytes 
2. Pools: Collections of blocks where all blocks in pool are of same size, will have different pools for different sizes of objects like (4,8,16 Bytes )
3. Arena: Collections of pools where all pools in arena are of same size, will have different arenas for different sizes of objects like (4,8,16 Bytes )

Garbage Collection:
when a value in memeory is no longer referenced by a variable then python interpreter will remove it automatically 
this process is called garbage collection

Reference Counting:
each object in python has a reference count, when the reference count is 0 then the object is deleted by garbage collector

```python
import sys
a = 10
print(sys.getrefcount(a))  # Shows reference count of A which is 2

b = 10 
print(sys.getrefcount(b))  # Shows reference count of B which is 3 

del a
print(sys.getrefcount(b))  # Shows reference count of B which is 2 
```

The Three Generations (Objects start in Generation 0 and move to Generation 1 and then to Generation 2)
1. Generation 0: Newly created objects (Young Generation)
2. Generation 1: Objects that have survived one garbage collection (Young Generation)
3. Generation 2: Objects that have survived two garbage collections (Old Generation)

weakref: is a module that provides a weak reference to an object, it is used to avoid circular references
meaning if an object is referenced by a weak reference then it will not be counted as a reference and will be garbage collected

Weak References is not supported in python for int, str, list, tuple, dict, set, etc,.

But it is supported for custom objects and classes


```python
import weakref

class MyList:
    def __init__(self, data):
        self.data = data
    
    def __getitem__(self, index):
        return self.data[index]
    
    def __repr__(self):
        return f"MyList({self.data})"

a = MyList([1, 2, 3])
b = weakref.ref(a)
print(b())  # <__main__.MyList object at 0x...>

del a
print(b())  # None (object was garbage collected)

# in the same example if b is created like a = b then it will not be a weak reference and will be a strong reference
# then event if a is deleted b will still be a reference to the object and will not be garbage collected

print(b)  # --> value of b will be the object address
```

Main root cause of memory leaks in python:

1. Circular References: when two objects reference each other and the reference count is not 0 then the objects will not be garbage collected
2. Unclosed Resources: when a resource is not closed then the memory will not be freed and will lead to memory leaks (Files, Database Connections, etc,)
3. Cache and Unhandled Global Variables: when a cache is not cleared or a global variable is not handled then the memory will not be freed and will lead to memory leaks
4. Exceptions: when an exception is not handled then the memory will not be freed and will lead to memory leaks

GIL: Global Interpreter Lock   (refer: https://www.youtube.com/watch?v=XVcRQ6T9RHo)

It makes python to run one thread at a time, so multiple threads cannot run in parallel.
meaning it will make only one thread to use python interpreter at a time.

Analogy: lets say i have a big 6 one way road but insted of allowing 6 cars to run parallelly i will allow only 1 car to run at a time.

Why is this is python memory management runs using reference counting and its on top of Cpython which is not thread safe 

meaning with out GIL if two thread are using same memory this might lead to data corruption or inconsistent state of the memory
so to avoid this python uses GIL to make sure that only one thread can use the memory at a time.

In multiprocessing we create multiple processes and each process has its own memory  and GIL  
Use for CPU bound tasks where we need to use multiple cores of the CPU. Example: Image processing, Video processing, etc,.

In multithreading we create multiple threads and each thread (Still not true parallelism and thread safe) memory and GIL are shared

Concurrent programming or Asynchronous programming:
Here we use asyncio to create multiple tasks and each task is a coroutine and each coroutine is a function that can be paused and resumed.
We only use one thread to handle multiple requests. Example: Web server, etc,.

```python 
import asyncio
import time

async def table_order(table_num, wait_time):
    print(f"🧑‍🍳 Table {table_num} placed order (wait {wait_time}s)")
    await asyncio.sleep(wait_time)  # Simulate network/DB wait
    print(f"✅ Table {table_num} food ready! Served.")
    return f"Table {table_num} meal complete"

async def restaurant():
    print("🏃‍♂️ Waiter (event loop) starts single-thread work...")
    start = time.time()
    
    # 5 tables all start "cooking" simultaneously
    orders = [
        table_order(1, 2),  # Slow network
        table_order(2, 1),  # Fast API  
        table_order(3, 3),  # Slow DB
        table_order(4, 0.5),# Quick cache
        table_order(5, 1.5) # Medium file I/O
    ]
    
    # Waiter serves ALL when ready (total 3s, not 8s sequential!)
    results = await asyncio.gather(*orders)
    print(f"🏆 All {len(results)} tables served in {time.time()-start:.1f}s")

# Run restaurant
asyncio.run(restaurant())
```

Deque: (https://youtu.be/34SNQHapJYE?si=uEFpus05jgv4bUBi)

helps to add and remove elements from both ends efficiently

from collections import deque
d = deque([1, 2, 3, 4, 5])

d.append(6) -> will add 6 to end
d.appendleft(0) -> will add 0 to start

d.pop() -> will remove and return the last item in this case 5
d.popleft() -> will remove and return the first item in this case 1

d.extend([7, 8, 9]) -> will add 7, 8, 9 to end
d.extendleft([-1, -2, -3]) -> will add -1, -2, -3 to start

d.rotate(-1) -> will rotate the deque by 1 position to clockwise
d.rotate(1) -> will rotate the deque by 1 position to anti-clockwise

How is it different from list:
Adding and removing from right/end   O(1) in list and O(1) in deque
Adding and removing from left/start  O(n) in list and O(1) in deque
Accessing elements by index          O(1) in list and O(n) in deque
Memory usage                         less in list and High in deque

Memoization: 
1. allows you to optimize a Python function by caching its output based on the parameters you supply to it
2. It can be used to optimize the programs that use recursion
3. @memoize_factorial

memory = {}
def memoize_factorial(f):
     
    # This inner function has access to memory
    # and 'f'
    def inner(num):
        if num not in memory:
            memory[num] = f(num)
            print('result saved in memory')
        else:
            print('returning result from saved memory')
        return memory[num]
 
    return inner
     
@memoize_factorial
def facto(num):
    if num == 1:
        return 1
    else:
        return num * facto(num-1)
 
print(facto(5))
print(facto(5)) # directly coming from saved memory

---------------------------------------------  Inheritance ---------------------------------------------

Inheritance: is a way to inherit (Accessing and using) attributes and methods from a parent class to a child class

Types of Inheritance:
1. Single Inheritance         A (Parent) --> B (Child)
2. Multi-level Inheritance    A (Parent) --> B (Child) --> C (GrandChild)
3. Multiple Inheritance       A (Parent) --> C (Child)    and B (Parent) --> C (Child)
4. Hierarchical Inheritance   A (Parent) --> B (Child)    and A (Parent) --> C (Child) 

super() --> used to call parent class method 


Method Resolution Order (MRO): is a way to determine the order in which methods should be called in a class
When obj.method() is called → Python searches: Class -> Parent Class -> GrandParent Class -> ... -> Object

MRO is critical for multiple inheritance to avoid ambiguity and ensure the correct method is called


```
class A:
    pass

class B(A):
    pass

class C(B):
    pass
```

How MRO works: object C is called then it will search for method in C, then B, then A, then Object
C.__mro__ --> (C, B, A, Object)


```python
class A:
    pass

class B(A):
    pass

class C(A):
    pass
class D(B, C):
    pass
```

How MRO works: object D is called then it will search for method in D, then B, then C, then A, then Object
D.__mro__ --> (D, B, C, A, Object)
If child has 2 parent classes then it will search for method in the first parent class and then the second parent class
left to right 

--------------------------------------------- Abstract Base Class ---------------------------------------------

Abstract Base Class: is a class that is not meant to be instantiated and is meant to be subclassed
it is used to define a common interface for a group of classes and enforce that a subclass to be implemented for sure 

abstractproperty (@property): we use this to convert a method to a property
abstractmethod (@abstractmethod): we use this enforce that a subclass to implement a method for sure making it mandatory

```
from abc import ABC, abstractmethod, abstractproperty

class Animal(ABC):

  @property
  @abstractmethod
  def colour(self):
    pass
  
  @abstractmethod
  def location(self):
    pass

  @abstractmethod
  def food_habits(self):
    pass
```
