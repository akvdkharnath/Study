Redis: Remote Dictionary Server (written in ANSI C)
- Start: redis-server start
- Restart: redis-server restart
- Stop: redis-server stop

Connect to Server: redis-cli -h host -p port -a password 

Basic Commands:
- redis-cli: Start server
- SELECT 10: Selects database 10 (Redis has databases 0-15)

Redis:
1. Stores everything in primary memory (in memory database)
2. R/W operations are extremely fast
3. Primary memory is in lesser in size and super costely
4. can also be used as primary DB like SQL
5. single threaded
6. Support Replication (Master-Slave, Data mirroring)
7. We can use several data types here.
8. Support Sharding (Partitioning)

Normal Database:
1. Stores everything in secondary memory
2. R/W operations are slow
3. Secondary memory is in abundant in size 


Memcached:
1. Data replication is not supported.
2. multi threaded (DIS)
3. We can only single data types here.

KEYS:
Will scan all the keys in ONE go, As redis is a single threaded server it will block all other request till then resulting timeout issues 

1. Never user in PRODUCTION 
2. Only user for debugging and testing 
3. User only on small data sets 
4. O(N) time complexity

SCAN:
Will scan and return a batch of keys at once and a cursor to the next batch, if cursor is 0  then scan is complete

1. good for production
2. very fast if there is huge data  
3. O(1) time complexity but per run


Supported Patterns:
* -> Any charater next or before it 
user* -> will return all keys starting with user
*user -> will return all keys ending with user
*user* -> will return all keys containing user anywhere in the key
user*profile -> will return all keys containing user at the start and profile at the end anywhere in the key


? -> Any single character
?? -> Any two characters

user? -> user1, user2, userA
user?? -> user12, user23, userA4
use?r -> use1r, use2r, useAr


[...] -> Matches any single character in the range

[A-Z] -> Matches any uppercase letter
[0-9] -> Matches any digit
[a-zA-Z] -> Matches any letter
[a-zA-Z0-9] -> Matches any letter or digit


[^...] -> Matches any single character not in the range
[^a-z] -> Matches any character not a lowercase letter

Search Types:
1. Object Inspection: Pulling all data into your code to filter it. Very slow for large datasets because of high network traffic.
2. Faceted Search (Set Intersection): Using Sets or Sorted Sets as indexes. Example: Finding "Engineers" in "London" using SINTER. This is the fastest way to filter in Redis.
3. Hashed Index/Keys: Using a consistent naming pattern (like user:email_hash) for instant O(1) lookups when you know the unique ID.

Transactions (MULTI/EXEC):
Redis transactions group commands to run them together without interruption.
- MULTI: Starts the transaction (commands are queued, not run yet).
- EXEC: Runs all queued commands at once.
- DISCARD: Cancels the transaction and clears the queue.

Note: Redis does NOT support SQL-like rollbacks. If one command fails during execution, the others will still run.

Durability (Fsync):
AOF (Append Only File) uses fsync() to save data to disk. 
- everysec (Default): Best balance. You only lose max 1 second of data if the system crashes.
- always: Safest but very slow.
- no: Fastest but risky data loss.
