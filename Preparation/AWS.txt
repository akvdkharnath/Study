SQS: Simple Queue Service 
Fully managed Queue Service, mainly used to decouple two services 

Decoupling: Producer and Consumer are independent of each other, they dont need to be online at a time 
Scale: Stores Any number of messages in the queue  with no limit 
Durability: Messages are stored in the queue and are not lost if the consumer is not available

Producer: The service that sends messages to the queue

Consumer: The service that receives messages from the queue 
they use polling to receive messages (long polling)
they can use batch messages to recive multiple messages at a time  


Queue: The storage for the messages

Types of SQS Queues:
Standard Queue: 
Messages are not processed in the order they are sent, processed at least once (1 or many times)

FIFO Queue: 
Messages are processed in the order they are sent, processed exactly once (1 time)
name must end with .fifo
IF created using api need to pass FifoQueue True 
        
--> Queue can not be converted from standard to fifo or vice versa


Message Lifecycle:
1. Producer: The service that sends messages to the queue
2. Consumer: Once Consumer receives the message 
3. In flight: Message is still in the queue but hidden for other consumers (this time is called visibility timeout)
4. Success: Message is processed successfully and deleted from the queue (DeleteMessage)
5. Failure: Message got crashed or failed to process, it will be retried for a given number of times then it will be moved to Dead Letter Queue
6. If no dead letter queue is configured, the message will be visible again after the visibility timeout
7. if message us still process we can increase the visibility timeout for that message  (ChangeMessageVisibility)


Sample Python Code:
import boto3
```python
# Initialize SQS client
sqs = boto3.client('sqs', region_name='us-east-1')
queue_url = 'https://sqs.us-east-1.amazonaws.com/123456789012/MyQueue'

# 1. Sending a message
sqs.send_message(
    QueueUrl=queue_url,
    MessageBody='Order ID: 5521',
    DelaySeconds=0
)

# 2. Receiving a message (Long Polling)
response = sqs.receive_message(
    QueueUrl=queue_url,
    MaxNumberOfMessages=1,
    WaitTimeSeconds=20  # Long Polling
)

messages = response.get('Messages', [])
for msg in messages:
    print(f"Processing: {msg['Body']}")
    
    # 3. Explicitly Delete after processing
    sqs.delete_message(
        QueueUrl=queue_url,
        ReceiptHandle=msg['ReceiptHandle']
    )
```

Alternatives to SQS: Azure (Azure Queue Storage), Google (Cloud Storage Queues)

SNS: Simple Notification Service 
Fully managed Pub/Sub messaging service, mainly used to decouple two services 

Decoupling: Producer and Consumer are independent of each other, they dont need to be online at a time 
Scale: Stores Any number of messages in the queue  with no limit 
Durability: Messages are stored in the queue and are not lost if the consumer is not available
Push-based: Unlike SQS, SNS is push-based, the producer pushes the message to the topic and the topic pushes the message to the subscribers

Topics: A logical access point and communication channel.
Publishers: The service that sends messages to the topic
Subscribers: The service that tune to the topic and receive messages from the topic
Messages: The data that is sent to the topic

Where SNS can Push Notifications: SQS, Lambda, HTTP, SMS, Email, Kinesis, S3, SES



Message Lifecycle:
1. Publisher: The service that sends messages to the topic
2. If no one is subscribed to the topic, the message will be gone 
3. Subscriber: Once Subscriber receives the message 
4. If subscriber is down, we can configure to retry for a given number of times then it will be moved to Dead Letter Queue

Sample Python Code:

```
import boto3

sns = boto3.client('sns', region_name='us-east-1')

# 1. Create a Topic
topic_response = sns.create_topic(Name='OrderUpdates')
topic_arn = topic_response['TopicArn']

# 2. Subscribe an SQS queue to the Topic
sns.subscribe(
    TopicArn=topic_arn,
    Protocol='sqs',
    Endpoint='arn:aws:sqs:us-east-1:123456789012:MyQueue',
    Attributes={
        'FilterPolicy': '{"event_type": ["order_cancelled"]}' # Only send cancellations
    }
)

# 3. Publish a Message
sns.publish(
    TopicArn=topic_arn,
    Message='Order #1234 has been cancelled',
    Subject='Alert: Cancellation',
    MessageAttributes={
        'event_type': {'DataType': 'String', 'StringValue': 'order_cancelled'}
    }
)
```

Delayed Queue: Messages are processed after a given delay
Dead Letter Queue: Messages that are not processed after a given number of attempts

Alternatives to SNS: Azure (Azure Service Bus topics), Google (Cloud Pub/Sub)

Event Bridge: 
Fully managed Event bus service for managing events with AWS Services or third party services

Event: A json describing the event
Rule: A rule that is used to route the event to a target
Target: A target that is used to receive the event

Main use cases:
1. Schedule Events: Cron jobs, periodic data processing
2. Events from AWS services: S3, SNS, SQS, etc like sending alerets based on server logs or events from S3 or SNS or SQS
3. Events from third party services: Slack, Twilio, Pager etc

If required we can save early events and get all the events retriggered later from the event bus

```
import boto3
import json

events = boto3.client('events')

# 1. Putting an event on the bus
response = events.put_events(
    Entries=[
        {
            'Source': 'com.mycompany.orders',
            'DetailType': 'OrderCreated',
            'Detail': json.dumps({
                'order_id': '12345',
                'status': 'new',
                'amount': 150.00
            }),
            'EventBusName': 'MyCustomBus'
        }
    ]
)
```

Alternatives to Event Bridge: Azure (Event Grid), Google (Cloud Pub/Sub)

EC2: Elastic Compute Cloud: 

Fully managed VM's in cloud
Will have OS level access to the instance, Once the EC2 instance is killed or stopped then data in the instance is lost
to solve this use EBS (Elastic Block Store)

AWS names instances like t3.large

Family (t): The "Specialty" (t=General Purpose, c=Compute, m=Memory, r=RAM, g=Graviton/ARM).
Generation (3): The age. Higher is newer, faster, and usually cheaper.
Size (large): How much RAM/CPU. Each size up usually doubles the resources and the price.


Types of EC2 Instances:
1. On-Demand: Pay as you go, no upfront cost, no commitment
2. Reserved: Pay for a period of time, no upfront cost, commitment
3. Spot: Bid for a period of time, no upfront cost, no commitment
4. Dedicated: Dedicated to a single customer, no shared resources

Use only if your application is not a containerized application
when we need to have full control over the underlying infrastructure like OS

ECS: Elastic Container Service
Fully managed container orchestration service, mainly used to deploy and manage containerized applications like Docker containers
using a config we can manage the number of containers and the resources they need

using fargate we can run the containers without managing the underlying infrastructure

Use only if your application is a containerized application and Kubernetes is not required
Only working with AWS and want to intigrate all services in AWS

Alternatives to ECS: Azure (AKS: Azure Kubernetes Service), Google (GKE: Google Kubernetes Engine)

EKS: Elastic Kubernetes Service

Nodes: workers that run the containers

Lambda: Fully managed serverless compute service for running code in response to events

Handler: entry point for the function 
Event: the data that is passed to the function
Context: the context of the function
Layers: the dependencies that are needed for the function

Cold Start: the first time the function is called, it takes longer to start up
Warm Start: the function is already running, it takes less time to start up

It can scale automatically to handle the traffic 

Max Execution Time: 15 minutes (hard limit).
Max Payload Size: 6 MB (Synchronous), 256 KB (Asynchronous).

```
import json
import os

def lambda_handler(event, context):
    # 1. Read environment variables
    db_url = os.environ.get('DB_URL')
    
    # 2. Extract data from event (e.g., from API Gateway)
    body = json.loads(event.get('body', '{}'))
    name = body.get('name', 'Stranger')
    
    # 3. Check remaining time
    if context.get_remaining_time_in_millis() < 100:
        return {"statusCode": 504, "body": "Timeout imminent!"}
        
    print(f"Hello {name} from Lambda!")
    
    return {
        'statusCode': 200,
        'body': json.dumps({'message': f'Success for {name}'})
    }
```

Alternatives to Lambda: Azure (Azure Functions), Google (Cloud Functions)



Alternatives to Lambda: Azure (Azure Functions), Google (Cloud Functions)

S3: Simple Storage Service

Fully managed object storage service for storing any type of data

Unlimited storage capacity
Durability: 99.999999999%
Availability: 99.99%
Allows Encryption, Versioning, Lifecycle Policies (Can set to delete after a certain period of time), etc
for uploading large files we can use multipart upload or upload file in chunks

For downloading files we can use pre-signed URLs or CloudFront to cache the files

Supports events like S3 events, SNS events, SQS events, etc

S3 Bucket can not be mounted as native volume in the operating system, but we can use tools to kind of mount it 
and view files like we view files in a directory


Object: A file and its metadata
Bucket: A container for objects

===========================================================================================

EBS: Elastic Block Storage:

Fully managed block storage service, unlike S3 we can mount it as native volume in the operating system
and view files like we view files in a directory

Unlimited storage capacity
Durability: 99.999999999%
Availability: 99.99%

Mainly used to store the data for the EC2 instance 

===========================================================================================

EFS: Elastic File System
Fully managed file storage service for storing any type of data

Unlimited storage capacity
Durability: 99.999999999%
Availability: 99.99%

lets say multiple services need to share the same data, we can use EFS to store the data and the services can mount it as a native volume in the operating system
and view files like we view files in a directory
